# ADR-0003 — Markdown + frontmatter YAML como contrato entre roles

- **Estado:** Aceptado · **Fecha:** 2026-07-06 · **Autor:** Fable · **Contexto:** Día 2 de Atlas

## Contexto

Los roles del pipeline se pasan artefactos entre sí (RN-2) y el output final de Atlas es un repo Markdown. Opciones: JSON intermedio (estricto para máquinas) renderizado a Markdown al final, o Markdown con frontmatter YAML validado como único formato de punta a punta.

## Decisión

Markdown + frontmatter YAML único, validado en dos capas: pydantic para el frontmatter (metadatos, inputs con hash, supuestos) y chequeo de headings obligatorios para el cuerpo.

## Consecuencias

- (+) Un solo formato: lo que valida el pipeline es literalmente lo que lee el humano y lo que se exporta — cero transformación final, cero divergencia entre formato interno y entregable.
- (+) Diffs de git útiles en cada etapa; Federico puede corregir un artefacto a mano y re-correr desde ahí (el hash de inputs invalida lo posterior).
- (+) Los LLM producen Markdown con secciones de forma más fiable que JSON complejo anidado.
- (−) El cuerpo es menos estricto que un JSON Schema — mitigado con headings obligatorios y el reintento con feedback (RN-4); si un campo necesita validación fuerte, se sube al frontmatter.
- **Trigger de revisión:** si un consumidor programático post-MVP necesita datos estructurados finos (p. ej. API pública), se agrega una vista JSON generada desde el frontmatter, no se reemplaza el formato.
