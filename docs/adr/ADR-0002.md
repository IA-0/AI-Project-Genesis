# ADR-0002 — Orquestador propio en Python, sin framework de agentes

- **Estado:** Aceptado · **Fecha:** 2026-07-06 · **Autor:** Fable · **Contexto:** Día 2 de Atlas

## Contexto

El pipeline del MVP son tres llamadas LLM secuenciales con validación determinística entre etapas. Opciones evaluadas: framework de agentes (LangChain/CrewAI), motor de flujos ya instalado (n8n), u orquestador propio (~200 líneas de Python).

## Decisión

Orquestador propio. Un framework de agentes agrega dependencias pesadas, abstracciones que esconden los prompts (lo que en una entrevista es exactamente lo que hay que poder mostrar) y churn de API notorio, a cambio de resolver problemas que el MVP no tiene: grafos dinámicos, memoria conversacional, tool-calling multi-agente. n8n queda descartado para el core por la misma razón: el flujo es lineal y la lógica de validación/reintento es más simple en Python que en nodos.

## Consecuencias

- (+) Cada prompt, contrato y decisión de control es visible y defendible; deps mínimas (ADR consistente con S-D2-6).
- (+) El reintento con feedback del validador (RN-4) se implementa exactamente como lo pide la spec, sin pelear contra el framework.
- (−) Retries/timeouts de red quedan a cargo de los SDKs oficiales — aceptado, es su trabajo.
- **Trigger de revisión:** si post-MVP aparecen más de ~5 roles, paralelismo entre roles o loops dinámicos, se reevalúa un framework (o n8n como capa de triggers).
